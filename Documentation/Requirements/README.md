# Requirements

Requirements are the product source of truth for intended behavior.

## Recommended IDs

- `FND-###` — reusable foundation capability
- `STORY-<NAME>-###` — story requirement
- `UX-###` — cross-project experience requirement
- `TECH-###` — technical requirement

## Requirement template

```markdown
# <ID> — <Title>

## Purpose

## Player / Product Goal

## Biblical Context

## Scripture References

## Scope

## Non-Goals

## Functional Requirements

## Acceptance Criteria

## Dependencies

## Foundation / Reuse Considerations

## Testing Requirements

## Open Questions
```

## Rule

A requirement describes what should exist and why. It should not unnecessarily prescribe implementation details.
