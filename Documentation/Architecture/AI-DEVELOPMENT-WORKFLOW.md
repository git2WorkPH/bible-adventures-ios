# Bible Adventure AI Development Workflow

## Purpose

Define how AI tools should be used to develop Bible Adventure without repeatedly reconstructing requirements or project history.

## Roles

### Human / Product Owner

Owns:
- product vision
- Biblical intent
- scope decisions
- requirement approval
- task approval
- trade-offs

### ChatGPT

Best used for:
- requirements discovery
- product reasoning
- architecture discussion
- repository assessment
- documentation
- reviewing proposed work

### Codex

Best used for:
- repository inspection when needed
- implementing approved tasks
- running tests
- making code changes
- fixing implementation issues within scope

### Continuity Kit

Provides:
- repeatable workflow
- task traceability
- project memory
- assessment process
- review process

## Standard lifecycle

```text
1. Define requirement
2. Analyze requirement
3. Assess existing repository
4. Identify reusable foundation
5. Generate tasks
6. Human approves tasks
7. Implement task
8. Run tests
9. Review task
10. Update session memory
11. Periodically reassess project
```

## Important boundary

The AI may recommend work. It must not silently convert recommendations into approved product scope.
