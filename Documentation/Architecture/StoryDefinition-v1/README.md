# StoryDefinition version 1 contract

Approved PA-004-T01 decision: ../Decisions/PA-004-STORY-COMPOSITION.md. Implemented type: BibleAdventure/Core/Models/StoryDefinition.swift. JSON examples here are synthetic documentation fixtures, absent from the production catalogue. Their Genesis reference is a structural placeholder, not a claim that the fixture dialogue occurs in Genesis. Matching runtime fixtures in StoryDefinitionTests exercise both StoryID identities.

Required top-level keys: schemaVersion (integer 1), contentVersion (nonempty compatibility identity), story, presentation, reflection, scripture array and questions array. Story requires id (typed StoryID), title, description and nonempty steps. A step has kind dialogue/objective/miniGame and exactly one corresponding dialogue/objective/activity payload. Unknown enum values and missing/contradictory required payloads reject the whole definition. Optional nil hint/endVerse fields may be omitted. Extra unknown JSON object keys are ignored by Codable for forwards-compatible metadata; this does not permit unknown schema versions.

Dialogue payload: speaker, text, reference, kind. Objective: id/title/instruction/type/reference/scripture/questionId/storyId, optional hint. IDs must be unique per objective/question; objective questionId must resolve. Scripture dialogue and nonempty objective scripture must exactly match a reviewed scripture record with the same reference. Scripture records include text/reference/translation. Questions require at least two nonempty options and an in-range correct index. Reflection requires id/prompt/scriptureReference. Presentation requires homeIntroduction/restartName/reflectionTitle/completionInvitation/readingLabel/readingURL; reading destination must be HTTPS at www.esv.org without embedded credentials.

References require a supported typed book, valid chapter and positive ordered verse range (maximum numeric verse 176). This catches structural errors, not every chapter's canonical verse count or source accuracy; editorial review remains mandatory. Currently supported books are the five Pentateuch books. Future books require a typed extension and review before their definitions load.

Recovery: repository rejects invalid/missing/malformed definitions before playable steps are exposed. Runtime presents existing content-unavailable recovery; no fallback executable story. New schema versions need a decoder/migration decision. New content versions do not reuse old step indices; current explicit New Adventure recovery retains incompatible saves until an intentional restart. Existing noah-2 content preserves 26 steps/objective identities and needs no progress migration. PlayerProgress storage schema is unchanged; per-story snapshots are retained with one selected runtime.

Typed mini-game identifiers map to compiled Swift behavior. Version 1 externalizes presentation/story/questions/reflection/quotations; matching configuration remains Swift, and configuring matching for a second production story is a PA-005 dependency. This contract does not claim every game or speaker is extensible from JSON.
