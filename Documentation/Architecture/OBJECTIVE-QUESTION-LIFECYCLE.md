# Objective and question lifecycle

Task: FND-BASE-T07

`ObjectiveQuestionSession` owns one question-backed objective. It accepts an existing `QuizQuestion`, objective identity, Scripture reference, and content-supplied explanations. No Biblical content is generated by the lifecycle.

Construction validates identifiers, options, answer index, explanations, and reference bounds. Answers keep their original option index as identity while their presentation order is shuffled once. Duplicate visible labels therefore cannot change correctness. An injected random generator makes this behavior reproducible in tests; production defaults to the system generator.

Transitions: inactive → answering → incorrect → answering (retry), or answering → completed. Invalid selections and actions do not mutate state. A wrong answer is a failed attempt, while the objective remains active. Retry clears only the selected answer and feedback. Completed sessions cannot be restarted or answered again.

The session exposes derived `ObjectiveState`, a retained hint/reference, and `LearningFeedback` containing correctness, explanation, and reference. Explanations are interpretation rather than direct Scripture and must be presented according to the approved Scripture policy by future UI integration.

`takeCompletion()` returns an `ObjectiveCompletion` once, with objective/question identities, reference, and a `.success` activity outcome. A coordinating caller can forward that outcome to `StoryEngine.apply(outcome:)`; the lifecycle itself does not choose the next story step. Copies are independent value snapshots, so the coordinator must retain a single session owner to preserve once-only consumption.

Runtime integration of prototype views is deferred. This task introduces no new Noah questions or content, scoring, reflection, or persistence.
